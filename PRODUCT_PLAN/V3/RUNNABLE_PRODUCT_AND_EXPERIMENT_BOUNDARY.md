# 可运行产品与实验资产边界

状态：当前交付边界  
日期：2026-10-03

## 1. 文档职责

本文细化 [V3 产品计划](PRODUCT_PLAN.md) 中可运行产品、用户项目工具和实验资产的边界，作为当前产品维护与验收的工作基线。

产品定位、Skill 职责和整体范围仍由 V3 产品计划统一定义。本文负责回答：

1. 当前产品保留哪些内容。
2. 具体环境、工具链和工程命令由谁维护。
3. 哪些内容用于验证产品效果，不构成产品运行条件。

## 2. 当前判断与用户决定

六项正式 Skill 的设计已经完备。2026-10-03 用户明确决定移除 Windows Execution Support Kit，并保持现有 Skill 设计。

本次调整范围为：

1. 移除根目录 `tools/`、`scripts/`、`environment/`。
2. 移除 Windows Execution Support Kit 对应工具级测试、打包流程和安装入口。
3. 保留六项正式 Skill 及各 Skill 自带的必要脚本、参考材料和模板。
4. Codex plugin manifest 暂留。
5. 具体环境、工具链、构建、测试、仿真和综合入口由用户项目及其已有约定维护。
6. 沿用现有版本标记，本次调整不另定发布版本。

现有竞赛报告和实验记录描述各自历史版本，保留原文。其中关于 Windows Execution Support Kit、工具测试、安装包或运行环境的表述，按对应时间、版本和实验输入理解。当前产品边界以本文件和 V3 产品计划为准。

以下三项继续属于实验资产：

1. Skill 行为 eval。
2. 最小处理器示例。
3. A/B 对照演示。

实验资产用于证明触发质量、方法有效性和产品收益。删除实验资产后，已接入 Codex 的 Skill 仍应能够正常调用。

## 3. 可运行产品

### 3.1 Codex plugin manifest

现有 Codex plugin manifest 暂留，负责声明产品身份、版本、Skill 路径和界面元数据。它接入 Codex 已有运行能力；会话、上下文、工具调用和任务执行继续由 Codex 承担。

### 3.2 Skill 与必要配套材料

六项正式 Skill 保持 [Skill 清单](../../skills/MANIFEST.md) 中的职责划分。每个 Skill 的 `SKILL.md` 定义其方法、输入、输出、权限边界和门禁，必要脚本、参考材料和模板随所属 Skill 保留。

Skill 自带脚本承担该方法中可确定执行的处理，例如文档检查和时序报告提取。其使用方式与依赖由所属 Skill 说明。具体处理器事实继续由用户项目维护。

### 3.3 用户入口

`README.md` 维护产品定位和使用入口，`USER_GUIDE.md` 维护用户操作说明。入口文档应与保留的 Skill 和 plugin manifest 一致，环境与工程命令说明引用用户项目已有约定。

## 4. 用户项目工具与执行

用户项目维护具体执行条件：

1. 所需工具、版本和平台条件。
2. 工具安装、探测与配置方式。
3. 构建、测试、仿真、综合和静态检查入口。
4. 工作目录、命令参数、退出状态和结果格式。
5. 缓存、日志、生成文件和工程证据位置。
6. Vivado 等专有工具的安装、许可证和使用边界。

Agent 先读取项目 `AGENTS.md` 和已声明的工具入口。缺少必要入口或执行条件时，报告具体缺口，并在用户授权范围内处理。环境变更继续遵守项目的授权约束。

Skill 指导需要取得什么证据，Agent 选择操作并解释结果，项目工具完成执行，设计师作出架构取舍。产品继续保持项目事实、设计者决定和工程证据各自的归属。

## 5. 产品内容与源仓库

当前产品内容为：

```text
processor-development-skills/
├── .codex-plugin/
├── README.md
├── USER_GUIDE.md
├── LICENSE
└── skills/
```

`skills/` 包含各 Skill 的入口及必要配套材料。产品计划、历史日志、竞赛报告和实验资产保留在源仓库各自位置。Windows Execution Support Kit 及其打包安装流程退出当前产品内容。

## 6. 实验资产

实验资产独立组织：

```text
experiments/
├── evals/
├── examples/
└── comparative-evaluation/
```

### 6.1 Skill 行为 eval

检查 Skill 是否在正确条件下触发，是否改变 Agent 行为，以及关键约束在真实会话中是否得到遵守。

### 6.2 最小处理器示例

为行为评测和演示提供固定输入，不成为产品支持的处理器模板或第二份处理器模型。

### 6.3 A/B 对照演示

按照 [Skill Package 对照评测方案](SKILL_PACKAGE_COMPARATIVE_EVALUATION.md) 比较 Control Team 和 Skill Team，用于形成比赛演示和效能证据。

实验失败会形成产品改进输入。实验按各自协议维护基线、环境和证据；既有运行记录保持原样。实验尚未执行不阻止 Skill 的基础功能验收。

## 7. 当前维护约束

本次调整保持六项 Skill 的现有方法体系、设计者权威和实验独立性。后续 Skill 维护继续依据具体任务和证据开展。

产品入口、当前计划和 plugin manifest 应与本文件一致。Windows Execution Support Kit 的环境探测、固定工具入口、工具级测试和可复现打包安装要求已经退出当前产品验收。

## 8. 可运行产品验收

1. Codex 可以发现并调用全部正式 Skill。
2. Skill 入口、必要脚本、参考材料和模板完整，相关链接有效。
3. `README.md`、`USER_GUIDE.md` 和 plugin manifest 与当前 Skill 范围一致。
4. 具体工程命令使用用户项目已声明的入口和环境约定。
5. 运行产物和工程证据进入用户项目指定位置。
6. 删除 `experiments/` 后，产品仍能调用 Skill。
7. 产品运行不依赖 V1 或 V2 Harness 状态。
8. 设计师拥有处理器架构判断和最终批准权，设计事实由用户项目维护。
