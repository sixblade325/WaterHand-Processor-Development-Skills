# WaterHand Processor Development Skills 作品简介

作者：计算机科学与技术学院 付家乐

产品版本：v3.0.3

日期：2026 年 9 月 6 日

GitHub：[sixblade325/WaterHand-Processor-Development-Skills](https://github.com/sixblade325/WaterHand-Processor-Development-Skills)

## 1. 作品背景与目标

在处理器开发中，工程师需要把有限的认知资源集中用于架构判断，权衡性能、时序、复杂度和验证成本。跨模块事实追踪、周期与异常路径核对、文档维护、实现审查和验证证据整理，同样消耗大量认知资源，其中相当一部分具有稳定的方法，可以重复执行并检查结果。

WaterHand Processor Development Skills 是一组面向处理器工程的认知方法包，以可安装、可组合、可验证的 Skill Package 的形式组织。产品从龙芯杯处理器开发经验中提炼方法，指导通用 Agent 接管高认知消耗、可重复、可检查的工程工作。

工程师持续掌握处理器目标、架构选择、设计事实和最终批准权，Agent 在授权范围内完成关联分析、文档、实现与验证。产品通过这种分工支持工程师围绕自己的架构判断，推进更多可验证的设计与实现任务。

## 2. 核心功能与使用方式

六项 Skill 分别定义一类任务的方法、输入输出与检查要求，工程师可按项目需要选择使用：

- `bootstrap-processor-project`：建立项目级协作规则，明确授权与事实归属。
- `organize-processor-docs`：渐进组织和维护处理器文档，提供可读、可检查的设计依据。
- `design-chisel-processor`：分析微架构方案，检查接口、周期关系和状态生命周期。
- `implement-chisel-processor`：落实已确认设计，同步维护 Chisel 源码、实现摘要与测试。
- `trace-vivado-timing-to-rtl`：将 Vivado 物理时序路径关联到 RTL 和 Chisel 源码，定位结构风险。
- `optimize-chisel-fpga-timing`：在授权范围内调整实现，通过功能回归和物理实现结果评估优化。

用户可在自己的处理器项目中指定 Skill 和任务范围。例如，工程师提交分支预测草稿后，Agent 分析未决条件及候选方案；工程师确认设计并授权后，Agent 更新文档、修改代码并运行测试，交付结果供工程师复核。

## 3. 主要创新与特点

每项 Skill 结合处理器领域知识，规定任务阅读顺序、分析框架、权限边界及产出质量要求，并收录典型缺陷与反例。Agent 据此分析关联条件、核对实现偏差，从测试和时序报告中提取证据，再形成有依据的修改候选。工程师可以沿分析过程复核，决定哪些方案值得实施。

文档组织采用人类与 Agent 共同维护的 Markdown 范式，区分处理器目标、具体设计和验证依据，按模块层次与跨模块协议建立阅读路径。同一设计事实集中维护，相关文档和源码通过链接关联。工程师可以直接修订材料，Agent 根据同一份项目事实继续工作，架构决定及其实现依据保存在用户项目与 Git 历史中。

## 4. 实践验证

产品通过顺序双发射开发对照、分支预测增量开发对照及人类工程师主导的分支预测开发进行验证。前两项由同等配置的 Codex 代理设计师，以控制设计师经验差异和重复任务的学习效应；人工案例展示工程师持续作出架构判断、Agent 推进关联工程工作的实际使用方式。

两次顺序双发射开发对照中，Skill 组均完成跨级数据转发，在通过相同功能检查的条件下，CoreMark 仿真 IPC 相对 Control 提高 34.93% 至 46.70%。分支预测对照中，Skill 组完成了功能实现与正式文档的同步维护；人工案例记录了工程师决定落实到设计、代码和定向测试的过程。

这些结果支持产品在已测任务中的工程支撑价值，性能数据限于 RTL 仿真。完整论证与指标见随附的[《设计文档》](DESIGN_REPORT.md)和[《实验补充说明》](EXPERIMENT_SUPPLEMENT.md)。

## 5. 使用模型与 API 调用方式

当前主要通过 Codex 使用和验证。对照实验采用 `gpt-5.6-sol`，主任务使用 `ultra` 推理设置，工程子任务使用 `high`；人工开发案例使用同一模型的 `high` 设置。

用户在 Codex 中提交任务，所选 Skill 与项目材料进入模型上下文，模型请求及工具执行由 Codex 根据用户配置完成。Skill Package 本身不直接实现模型 API 客户端，账户认证和模型访问由使用者配置。其他具备相应 Skill 加载、文件访问和工具调用能力的 Agent 开发工具可按其接口接入。

配套环境与工具链契约明确工具要求，Windows 脚本提供工具探测、命令调用和结构检查入口，减少重复的工具探索。当前支持 Windows x86-64。产品采用木兰宽松许可证第 2 版（MulanPSL-2.0），源码、Skill 和使用说明见文首 GitHub 仓库。
